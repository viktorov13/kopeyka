# Семейные расходы

Учёт расходов через Telegram и общую веб-панель. Бот понимает обычный текст, определяет сумму, категорию и дату, сохраняет покупки и отвечает на вопросы о тратах. Каждый пользователь бота работает только со своими записями; веб-панель показывает расходы всей семьи.

Бэкенд написан на Go, данные хранятся в PostgreSQL 18. Фронтенд на HTML, CSS и JavaScript встроен в Go-приложение и не требует отдельной сборки. Для разбора сообщений используется настраиваемая LLM с поддержкой инструментов: локальная Ollama или внешний совместимый API.

## Возможности

- Создание, просмотр, изменение и удаление расходов обычными сообщениями в Telegram.
- Уточняющий диалог, если не хватает суммы или найдено несколько подходящих записей.
- Веб-панель с CRUD, поиском, фильтрами по владельцу, периоду и категории, общими суммами и разбивкой по категориям.
- Семь категорий: еда, транспорт, жильё, развлечения, здоровье, покупки, другое.
- Изоляция расходов в боте, проверка аргументов инструментов и защита от повторной обработки Telegram-сообщений.
- Автоматические миграции, хранение данных в Docker volumes и REST API.

## Быстрый запуск с локальной моделью

Полный Docker-вариант работает на Windows, macOS и Linux: приложение, PostgreSQL и Ollama запускаются вместе. Модель в текущей конфигурации использует CPU. Для ускорения на Mac с Apple Silicon или Windows с поддерживаемой видеокартой используйте нативную Ollama — инструкции приведены ниже.

Нужны Git и Docker с Docker Compose v2. Go, Node.js и отдельная установка Ollama для полного Docker-варианта не требуются.

| Система | Подготовка |
| --- | --- |
| Windows | Установите [Git](https://git-scm.com/downloads/win) и [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/). В Docker Desktop используйте Linux-контейнеры; рекомендуемый вариант — WSL 2. Запустите Docker Desktop до выполнения команд. |
| macOS | Установите Git и [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/) для своего процессора: Apple Silicon или Intel. Запустите Docker Desktop. |
| Linux | Установите Git, [Docker Engine](https://docs.docker.com/engine/install/) и [плагин Compose](https://docs.docker.com/compose/install/linux/). |

### Windows: PowerShell

Откройте PowerShell и скачайте проект:

```powershell
git clone https://github.com/viktorov13/kopeyka.git
cd kopeyka

if (-not (Test-Path .env)) {
    Copy-Item .env.ollama.example .env
}
notepad .env
```

В открытом файле укажите `TELEGRAM_BOT_TOKEN` и сохраните изменения. Если проект уже скачан, сначала перейдите в его каталог; повторное клонирование не требуется.

### macOS и Linux: Терминал

```sh
git clone https://github.com/viktorov13/kopeyka.git
cd kopeyka

test -f .env || cp .env.ollama.example .env
```

Откройте `.env` в текстовом редакторе и укажите `TELEGRAM_BOT_TOKEN`. Если проект уже скачан, выполняйте команды из существующего каталога. Команды копирования выше сохраняют существующий `.env` вместе с токеном.

### Запуск на любой из этих систем

Токен выдаёт [@BotFather](https://t.me/BotFather) через `/newbot`. Без токена работает веб-панель, бот отключён. Вписывайте токен непосредственно в локальный `.env`; публикуемые примеры оставлены пустыми.

Запустите приложение, PostgreSQL и Ollama одной командой:

```sh
docker compose -f compose.yaml -f compose.ollama.yaml up --build -d
```

При первом запуске сервис подготовки скачает `qwen3:4b-instruct-2507-q4_K_M` — около 2,5 ГБ. Приложение запустится после загрузки модели и готовности базы. Откройте [http://localhost:8080](http://localhost:8080).

```sh
# Состояние и журнал запуска
docker compose -f compose.yaml -f compose.ollama.yaml ps -a
docker compose -f compose.yaml -f compose.ollama.yaml logs -f app ollama-model

# Остановка с сохранением расходов и модели
docker compose -f compose.yaml -f compose.ollama.yaml down
```

Если установлен `make`, эти команды также доступны как `make ollama-up`, `make ollama-logs` и `make ollama-down`. В обычном PowerShell используйте команды `docker compose` напрямую. Данные и веса модели хранятся в именованных томах. Опция `down -v` удаляет их.

Скорость зависит от оборудования; если обработка не укладывается в таймаут, используйте нативную Ollama с ускорением или другую модель с поддержкой инструментов. Первый запрос после запуска или простоя может включать загрузку модели в память. API-ключ не нужен. Интернет требуется для загрузки образов и модели, а также для работы Telegram.

При запуске на другом компьютере создаётся новая база. GitHub содержит исходники и примеры настроек; существующие расходы и локальный `.env` нужно переносить отдельно. Для одного Telegram-токена запускайте только один экземпляр бота.

## Telegram

Откройте личный чат с созданным ботом и нажмите «Начать». Члены семьи пишут одному боту в отдельных личных чатах. Telegram ID владельца определяется автоматически. Используется long polling: домен, HTTPS и webhook для бота не нужны.

| Сообщение | Результат |
| --- | --- |
| `кофе 350` | Новая трата: 350 рублей, еда, сегодня |
| `такси 1200 вчера` | Новая трата на транспорт за вчера |
| `сколько потратил на еду в этом месяце` | Сумма своих расходов на еду |
| `покажи траты за неделю` | Свои расходы за последние семь календарных дней |
| `последнее было не 350, а 450` | Исправление суммы последней созданной траты |
| `удали такси` | Поиск и удаление; при нескольких совпадениях — уточнение |
| `измени #12 категорию на покупки` | Изменение конкретной своей записи |
| `удали #12` | Удаление своей записи по ID |

ID виден в списке расходов; вместо `#12` используйте полученный номер. `/start`, `/help` и `помощь` показывают подсказки. `/cancel` и `отмена` очищают контекст разговора, сохраняя расходы. За одно сообщение бот изменяет не более одной траты.

Категорию выбирает модель по смыслу покупки. Продукты и напитки для людей, включая энергетики, относятся к еде; корм и обычные товары для животных — к покупкам; ветеринарные услуги и лекарства — к здоровью. Явно указанная разрешённая категория имеет приоритет.

Если бот не отвечает, проверьте журнал `app`. После изменения `.env` повторите `up -d` с теми же Compose-файлами: `restart` не применяет новое окружение. Для одного токена должен работать один процесс polling; у бота не должно быть активного webhook.

## Нативная Ollama на macOS и Windows

В этом варианте Ollama работает на самом компьютере, а приложение и PostgreSQL — в Docker Desktop. На Apple Silicon используется Metal; на Windows ускорение зависит от поддерживаемой видеокарты и драйвера. См. [поддержку оборудования Ollama](https://docs.ollama.com/gpu) и [Ollama для Windows](https://docs.ollama.com/windows).

Если ранее запускали полный Docker-стек, сначала остановите его из того же каталога проекта:

```sh
docker compose -f compose.yaml -f compose.ollama.yaml down
```

Выполняйте остановку без `-v`: расходы и скачанная контейнерная модель сохранятся. Затем выберите инструкцию своей системы.

### macOS: Ollama с Metal

1. Установите [Ollama для macOS](https://ollama.com/download/mac). При установке приложения откройте его один раз и разрешите добавить команду `ollama` в PATH, если появится такой запрос. При установленном Homebrew доступна команда `brew install ollama`.
2. Для запуска вручную завершите уже работающий сервер Ollama: выйдите из приложения через меню Ollama → Quit либо остановите Homebrew-службу командой `brew services stop ollama`, если используете её. Затем в отдельном окне Терминала запустите:

   ```sh
   OLLAMA_CONTEXT_LENGTH=8192 OLLAMA_NO_CLOUD=1 ollama serve
   ```

3. В другом окне Терминала скачайте модель и проверьте сервер:

   ```sh
   ollama pull qwen3:4b-instruct-2507-q4_K_M
   curl http://localhost:11434/api/version
   ```

Если сервер уже настроен как приложение или служба с контекстом 8192 и `OLLAMA_NO_CLOUD=1`, используйте его. Одновременно нужен только один сервер на порту `11434`. На Intel Mac этот вариант использует CPU; ускорение Metal относится к Apple Silicon.

### Windows: нативная Ollama

1. Установите [Ollama для Windows](https://ollama.com/download/windows). Для GPU нужен поддерживаемый адаптер и драйвер, указанные в [системных требованиях](https://docs.ollama.com/windows).
2. Выйдите из приложения Ollama через значок в системном трее, если оно запущено. Откройте новое окно PowerShell и запустите сервер:

   ```powershell
   $env:OLLAMA_CONTEXT_LENGTH = "8192"
   $env:OLLAMA_NO_CLOUD = "1"
   ollama serve
   ```

3. Во втором окне PowerShell скачайте модель и проверьте сервер:

   ```powershell
   ollama pull qwen3:4b-instruct-2507-q4_K_M
   Invoke-RestMethod http://localhost:11434/api/version
   ```

Если команда `ollama` не найдена после установки, заново откройте PowerShell. Как и на macOS, для запуска вручную оставьте окно с `ollama serve` открытым, пока работает бот.

### Подключение приложения к нативной модели

Для обеих систем используйте `.env`, созданный по инструкции быстрого запуска. Сохраните `TELEGRAM_BOT_TOKEN` и проверьте настройки LLM:

```dotenv
BOT_MODE=llm
LLM_BASE_URL=http://host.docker.internal:11434/v1
LLM_API_KEY=
LLM_MODEL=qwen3:4b-instruct-2507-q4_K_M
LLM_TIMEOUT=60s
LLM_MAX_STEPS=6
LLM_REASONING_EFFORT=none
```

Используйте полный тег Instruct-модели: короткий `qwen3:4b` может обозначать другую версию. Из каталога проекта запустите только базовый Compose:

```sh
docker compose -f compose.yaml up --build -d --wait
```

`host.docker.internal` — адрес компьютера из контейнера Docker Desktop. Проверьте доступ из приложения:

```sh
docker compose -f compose.yaml exec -T app wget -q -O - http://host.docker.internal:11434/api/version
```

Если сервер отвечает на компьютере, но проверка из контейнера не проходит, проверьте сетевые настройки и firewall Docker Desktop. До устранения соединения можно использовать полный Docker-вариант из быстрого запуска.

При нативной модели запускайте приложение с одним `compose.yaml`: подключение `compose.ollama.yaml` снова направит запросы в контейнерную Ollama. Для остановки приложения и базы используйте `docker compose -f compose.yaml down`. При ручном запуске нативного сервера его можно остановить через `Ctrl+C` в соответствующем окне терминала.

Отправьте боту сообщение, затем выполните на компьютере:

```sh
ollama ps
```

Столбец `PROCESSOR` показывает фактическое использование CPU/GPU. До первого запроса список может быть пустым; при нехватке памяти модель может использовать CPU частично или полностью. Панель доступна по [http://localhost:8080](http://localhost:8080).

## Другие варианты запуска

### Внешний совместимый API

Создайте `.env` из `.env.example`, если файла ещё нет. Заполните `TELEGRAM_BOT_TOKEN`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, установите `BOT_MODE=llm` и выполните `docker compose up --build -d`.

Требуется API **Chat Completions с function/tool calling**. Базовый URL указывается без `/chat/completions`: приложение добавляет путь само. Укажите точное имя доступной модели провайдера. API только с Responses без Chat Completions не подходит. `LLM_REASONING_EFFORT` оставьте пустым, если провайдер его не поддерживает.

При внешнем API сообщения и необходимые результаты поиска расходов передаются выбранному провайдеру. У локального сервера без авторизации `LLM_API_KEY` может быть пустым.

### Демонстрация без модели

`docker compose up --build -d` без `.env` запускает веб-панель с `BOT_MODE=rules`. Для бота достаточно токена Telegram. Этот режим разбирает ограниченный набор фраз; для полноценного понимания сообщений используйте `llm`. Автоматического переключения с LLM на правила при ошибках нет.

## Веб-панель и доступ

Панель управляет расходами всех пользователей. Владелец выбирается из списка или задаётся положительным Telegram ID. При пустой базе первую запись можно создать в боте либо вручную в панели. Бот и панель работают с одной базой.

У панели и REST API нет авторизации. По умолчанию Compose публикует HTTP только на `127.0.0.1`; PostgreSQL и контейнерная Ollama не публикуют порты на хост. Перед открытием панели в интернет нужно добавить контроль доступа. Адрес `localhost` доступен только на компьютере, где запущен проект. Telegram Mini App в эту версию не входит.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт панели на хосте в Compose; по умолчанию `8080` |
| `APP_TIMEZONE` | Часовой пояс дат и периодов; по умолчанию `Europe/Moscow` |
| `TELEGRAM_BOT_TOKEN` | Токен BotFather; пустое значение отключает Telegram |
| `BOT_MODE` | `llm` или `rules`; без настройки — `rules` |
| `LLM_BASE_URL` | URL Chat Completions API; по умолчанию `https://api.openai.com/v1` |
| `LLM_API_KEY` | Ключ провайдера; для локальной Ollama не требуется |
| `LLM_MODEL` | Имя модели; обязательно в режиме `llm` |
| `LLM_TIMEOUT` | Таймаут сообщения: `1s`–`60s`; по умолчанию `20s` |
| `LLM_MAX_STEPS` | Лимит шагов на сообщение: от 2 до 12; по умолчанию 6 |
| `LLM_REASONING_EFFORT` | Необязательная настройка; для выбранной Ollama-модели — `none` |
| `DATABASE_URL` | Подключение PostgreSQL при прямом запуске Go; Compose задаёт его сам |
| `HTTP_ADDR` | Адрес Go HTTP-сервера; по умолчанию `:8080` |

`compose.ollama.yaml` задаёт внутренний адрес Ollama, режим `llm`, пустой ключ и модель по умолчанию; `.env` позволяет выбрать другую модель и таймаут. `.env` читает Docker Compose. При прямом запуске Go переменные нужно передать процессу самостоятельно.

Реальные токены и ключи храните только в локальном `.env` или в секретах среды размещения. `.env` исключён из Git и контекста Docker; публикуются только примеры без значений секретов.

## Разработка и проверки

Для запуска без Docker нужны Go 1.24+ и PostgreSQL 18. Подготовьте базу и передайте подключение:

```sh
export DATABASE_URL='postgres://expenses:expenses@localhost:5432/expenses?sslmode=disable'
export BOT_MODE=rules
go run ./cmd/server
```

Миграции применяются при старте. Поиск использует Unicode-сопоставление PostgreSQL 18.

```sh
make check       # Go-тесты и go vet
make test-race   # Тесты с детектором гонок
make build       # Сборка bin/expenses
```

Без `TEST_DATABASE_URL` интеграционные тесты пропускаются. Полная проверка с отдельной временной PostgreSQL, без локальной установки Go:

```sh
make test-docker
docker compose -f compose.test.yaml down
```

Тестовый Compose использует отдельный проект и временную базу. Проверки включают CRUD, фильтры и суммы, миграции, изоляцию владельцев, повторы Telegram-сообщений, контекст и откат при ошибках LLM. Обычные тесты подменяют ответы провайдера и не обращаются к настоящей модели.

Для интеграционных тестов с собственной отдельной базой и проверки настоящей нативной Ollama:

```sh
export TEST_DATABASE_URL='postgres://expenses:expenses@localhost:5432/expenses_test?sslmode=disable'
make test-integration

export TEST_OLLAMA_URL=http://localhost:11434/v1
export TEST_OLLAMA_MODEL=qwen3:4b-instruct-2507-q4_K_M
make test-ollama
```

`test-ollama` проверяет основные сценарии бота и категории по изменениям в PostgreSQL. Нужны загруженная модель и доступная Ollama. Временная схема удаляется после теста; реальные сообщения в Telegram не отправляются. После смены модели повторите проверку: качество и скорость зависят от неё и оборудования. Все команды: `make help`.

## REST API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/expenses` | Список расходов и итоговые суммы |
| `POST` | `/api/expenses` | Создать расход |
| `PATCH` | `/api/expenses/{id}` | Изменить переданные поля |
| `DELETE` | `/api/expenses/{id}` | Удалить расход, ответ `204` |
| `GET` | `/api/users` | Владельцы и их суммы |
| `GET` | `/api/config` | Категории, дата, часовой пояс и режим |
| `GET` | `/healthz` | Доступность приложения и базы |

Фильтры списка: `user_id`, `from`, `to`, `category`, `search`, `limit`, `offset`. Даты — `YYYY-MM-DD`, границы периода включаются. `total`, `total_amount` и `category_totals` относятся ко всем подходящим расходам, а не только к странице.

Пример создания с условным владельцем:

```sh
curl -sS http://localhost:8080/api/expenses \
  -H 'Content-Type: application/json' \
  -d '{"user_id":42,"amount":"350.00","category":"еда","spent_at":"2026-01-15","comment":"кофе"}'
```

Сумма принимается и возвращается десятичной строкой. Поля: `id`, `user_id`, `amount`, `category`, `spent_at`, `comment`, `created_at`, `updated_at`. Ошибки имеют формат `{"error":"Описание ошибки"}`. `/healthz` проверяет базу; `bot_enabled` в `/api/config` означает наличие токена, а не проверку подключения к Telegram или модели. Секреты через API не возвращаются.

## Устройство и допущения

```text
cmd/server         HTTP-сервер и Telegram polling
internal/agent     клиент LLM, инструкции и инструменты расходов
internal/bot       Telegram, обработка сообщений и контекст
internal/expenses  валидация, PostgreSQL и миграции
internal/httpapi   REST API и раздача фронтенда
internal/config    проверка конфигурации LLM
web/static         интерфейс панели
```

Один Go-процесс обслуживает HTTP и Telegram через общий слой операций. Модель получает только разрешённые инструменты без доступа к SQL; владелец определяется сервером по отправителю Telegram и проверяется при чтении и записи.

Изменение расходов, контекст и результат обработки Telegram-сообщения сохраняются в одной транзакции. Повторный `update_id` не повторяет изменение; при ошибке модели изменения откатываются. Контекст LLM разделён по пользователям, ограничен по размеру, действует 24 часа после последнего обновления и переживает перезапуск. Ответ Telegram при сбое доставки может прийти повторно.

Суммы хранятся целым числом копеек, валюта — рубль. Поддерживается одна семья. «За неделю» — сегодня и шесть предыдущих дней; «последняя трата» — последняя созданная запись. Мультивалютность, отдельные семейные аккаунты и веб-авторизация в эту версию не входят.
